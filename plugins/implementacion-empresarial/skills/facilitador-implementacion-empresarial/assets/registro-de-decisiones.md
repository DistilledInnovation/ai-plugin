# Registro de decisiones de implementación

Flujo: ___ (`FLU-__`)  Contrato: `workflow-contract.yaml` (madurez: ___, fecha: ___)
Quién aprueba las decisiones de implementación (rol): ___
Última actualización: ___

Un solo registro para todo el plugin: cada skill agrega aquí sus decisiones. Los IDs `DEC-nn` continúan la numeración del diseño (si el diseño terminó en `DEC-07`, la primera de implementación es `DEC-08`) y nunca se reutilizan.

**Regla:** todo valor propio del cliente (plataforma, plazos, umbrales, retención, roles aprobadores, horarios, canales, modelos permitidos) entra como decisión, aunque quede **Pendiente**. Ningún valor queda implícito ni "por defecto". Sin credenciales, direcciones reales ni datos personales: los accesos se describen como capacidades y roles.

## 1. Decisiones

| ID | Decisión | Alternativas consideradas | Dueño (rol que decide) | Fecha | Aprobación (estado y quién) | Procedencia | Toca (IDs del contrato o del diseño) |
|---|---|---|---|---|---|---|---|
| `DEC-__` | | | | | Pendiente / Aprobada / Rechazada / Con cambios — por ___ | Decisión / Recomendación / Supuesto | |

Estados de aprobación: **Pendiente** (nadie aprobó todavía), **Aprobada**, **Rechazada**, **Con cambios** (aprobada si se cambia algo; anota qué).
